# 截图指南 — Landing Page 真实截图拍摄手册

页面 `index.html` 目前所有演示图是纯 CSS 模拟界面。按本指南拍 3 张真实截图、
放入 `assets/` 并替换对应 `<figure data-shot="…">` 后，展示页即为成品。

小功能合集（视觉分析 / 完整 HTML / 对话改配置 / 任意端点 / MCP / 配置导出）
为紧凑卡片，无演示图，不需要截图。

---

## 通用准备（每张截图都适用）

- **窗口**：浏览器窗口约 1440×900（或 1600×1000），侧边栏保持默认宽度。
  Windows 显示缩放 150%/200% 时截出的图更清晰（等效 2x）。
- **浅色主题**：系统与 Chrome 都用浅色模式，与页面浅色风格一致。
- **干净画面**：`Ctrl+Shift+B` 隐藏书签栏；关闭 DevTools；无关标签页先关掉；
  扩展栏图标过多时收起。
- **截取范围**：整个浏览器窗口（含标签条、地址栏、侧边栏），不要只截侧边栏。
  Windows 用 `Win+Shift+S` 框选，或用截图工具的「窗口」模式。
- **隐私**：截图前把 API Key 换成假值（如 `sk-test123`）或事后打码；
  不要暴露真实密钥、邮件、历史记录。
- **对话重置**：每张截图建议开新对话（对话区清空），保证画面干净、叙事聚焦。

## 替换方法（3 张通用）

拍好的图存为 `assets/shot-<id>.png`（id 见下），然后在 `index.html` 里找到：

```html
<figure class="shot" data-shot="<id>">
  <div class="mock"> … </div>   ← 删掉这一整个 div
</figure>
```

替换为：

```html
<figure class="shot" data-shot="<id>">
  <img src="assets/shot-<id>.png" alt="功能演示" width="1600" height="1000" loading="lazy">
</figure>
```

`.shot > img` 的样式已写好（圆角、边框、阴影、等比缩放），直接换即可。

## 逐张清单

### 1. `hero` — 首屏主图（网页问答）

| 项目 | 内容 |
| --- | --- |
| 去哪 | `https://zh.wikipedia.org/wiki/大语言模型`（或任意长文页面） |
| 模型 | glm-4.7（默认配置） |
| 问什么 | `这页讲了什么？给我 3 条要点` |
| 期望 | 出现一条 `get_page_content · 完成` 的折叠轨迹；回复 3 条要点，且注明来源是当前页面 |
| 截图时机 | 回答完整显示后；轨迹保持**折叠**状态 |
| 注意 | 模拟文案无需与截图站点一致——模拟图会被这张截图整体替换 |

### 2. `qa` — 核心：读得到动态页面

这张图对应核心卖点「普通 agent fetch 链接只能拿到没跑过 JS 的空壳，本扩展读的是浏览器里渲染完成的页面」，因此**必须选动态渲染的页面**：

| 项目 | 内容 |
| --- | --- |
| 去哪 | 动态加载的信息流页面，任选：① 知乎热榜 `https://www.zhihu.com/hot`（已登录状态更有说服力——顺便演示登录后内容读得到）② 微博话题页 ③ 其他需要 JS 渲染才有内容的站点 |
| 模型 | glm-4.7 |
| 问什么 | `这个信息流里大家主要在讨论什么？` |
| 期望 | 轨迹 `get_page_content` **展开**，能看到提取出的动态渲染内容（若用知乎，轨迹里应出现热榜条目文本而非空 HTML）；回复归纳 3 条左右主题并注明来源 |
| 截图时机 | 轨迹展开、回答完成后 |
| 注意 | 这张是全页最有说服力的图——如果 AI 读不到内容（提取失败标注），先确认该标签页在「上下文」中被勾选、页面已完全加载 |

### 3. `tabs` — 核心：全程浏览器内 + 多标签对比

| 项目 | 内容 |
| --- | --- |
| 去哪 | 两个标签页：`https://github.com/pricing` 和 `https://about.gitlab.com/pricing/` |
| 模型 | glm-4.7 |
| 问什么 | 先点顶部「上下文」，**勾选这两个标签页**（下拉面板保持展开），再问 `对比这两页的免费版有什么差异？` |
| 期望 | 回复给出对比表格（CI 分钟数、团队人数限制等），注明两个来源页 |
| 截图时机 | 表格回答完成后；**上下文下拉面板保持展开**、能看到两个勾选 |
| 注意 | 当前活动标签页建议是 GitHub Pricing（左侧网页区显示定价内容更直观） |

## 发布到 GitHub Pages

1. 把 `index.html`（及之后的 `assets/`）提交并推送到 `main`。
2. 仓库页 **Settings → Pages**：
   - Source 选 **Deploy from a branch**
   - Branch 选 **main** / **(root)** → Save
3. 1–2 分钟后访问：<https://oashua.github.io/llm_browser_ext/>
4. 之后每次 push 到 main，Pages 自动更新。

（单 HTML + 常规命名的 assets 无需 `.nojekyll`；若将来加入以下划线开头的资源目录，再在根目录加一个空 `.nojekyll`。）
